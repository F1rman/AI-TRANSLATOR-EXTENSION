## Використання

Оновіть розширення в `chrome://extensions` кнопкою перезавантаження на його картці; локальна збірка — `extension/dist`. Уже відкриті сайти також перезавантажте. Якщо встановлюєте ZIP, розпакуйте його й завантажте папку з manifest.json у режимі розробника.

Натискання на мову відкриває список із пошуком за українською, англійською, власною назвою або кодом. Власні назви мов і старі налаштування збережено.

Для картинки: правий клік на публічному статичному PNG/JPEG/WebP → «Перекласти картинку — Pro». Нова вкладка використовує поточні мови, показує оригінал/результат і кнопку завантаження PNG. Ліміт вхідного файла — 10 МБ і 20 МП. URL data/blob, GIF/SVG та зображення, що потребують cookies сайту, не підтримуються.

`dev.watersport@gmail.com` отримав безстроковий Pro: 5 успішних картинок на добу UTC. На момент передачі залишок — 5/5; тестові завдання використали окремий тимчасовий акаунт. Для появи Pro достатньо заново відкрити popup або оновити стан акаунта; оновлювати Firebase token через зміну тарифу не потрібно. Обидва тарифи мають 20 000 текстових символів на добу. Оплати немає.

## Реалізація та розгортання

- Короткий текст перевіряє результат через 250/500/750/1000 мс замість фіксованих 1400–1500 мс. Звичайний GET завдання виконує два читання Firestore без транзакції відновлення.
- Текстовий профіль з reasoning none не змінює запити інших клієнтів AI API. Durable jobs, перевірка власника, idempotency, відновлення та транзакційні квоти збережені.
- Картинки: vision розпізнає й перекладає всі текстові ділянки у перевірену карту замін; image editor отримує точні рядки. Обидва етапи разом обмежені 300 секундами. Початкове пряме редагування без карти пропускало арабський і японський текст, тому воно замінене двоетапною обробкою.
- AI API: `gpt-api-00004-jg2`; backend: `ai-translator-api-00003-vfv`, регіон europe-west1. Мінімум instances залишено 0. Секрети залишаються лише на сервері.
- Bucket `ai-translator-ext-images` приватний, з Uniform Access, Public Access Prevention і вимкненим soft delete. Доступ власника завершується через 24 години; lifecycle видаляє файли асинхронно. Помилки й скасування запускають негайну спробу очищення.
- Політика приватності, сторінки допомоги й матеріали Store оновлені. Нових Chrome permissions або Google OAuth scopes немає.

## Перевірки

Пройшли 33 тести розширення, 87 backend-тестів, 121 тест AI API, TypeScript і browser QA зібраного розширення. Перевірено пошук мов, теми, Free/Pro gate, PNG download, втрату мережі, відновлення після втрати POST-відповіді/перезапуску worker, скасування та вихід під час upload.

Живий текстовий pipeline пройшов перевірки Cloud Tasks/OIDC, квоти, повторних запитів і скасування. Живий image pipeline пройшов створення PNG, ізоляцію власника, анонімну відмову Storage, списання один раз, скасування/повернення резерву та очищення. Фінальна картинка з українським, арабським і японським текстом коректно перекладена англійською; композицію збережено. Час цього завдання — 21,171 с. Це перевірка одного прикладу, не гарантія безпомилкового перекладу довільних зображень.

Додатково перевірено збій Firestore після завершення й втрату підтвердження commit: уже створений PNG залишається доступним, квота не списується повторно, а невизначене завершення відновлюється через Cloud Tasks.

Справжній інтерактивний Google-вхід у звичайному Chrome автоматично не тестувався. UI-перевірки використовують контрольований транспорт; live smoke використовує окремі адміністративні fixtures, без підміни Firebase Google-токенів.

## Виміри затримки

20 коротких запитів до прямого AI endpoint у кожному запуску, без черги, Firebase user auth і розширення:

| Показник | До | Після |
|---|---:|---:|
| Warm p50 | 1410,8 мс | 1332,2 мс |
| Warm p95 | 3156,3 мс | 6828,6 мс |

Перший запит відокремлений від warm-вибірки. Cold start не був підтверджений; production instances примусово не зупинялися. Вибірка мала, а p95 після зміни погіршився через повільну відповідь провайдера. Результати не доводять стабільного прискорення самого AI; основна гарантована зміна — коротше клієнтське очікування й менше читань БД. Логи містять окремі числові таймінги auth, Firestore, enqueue, queue та AI, без текстів і зображень.
